# Trash: restore, delete for good, 30 days

**Asked.** A real trash. Design first (in Bangla), then build it: parent-child at every depth (attachment → note → folder → folder → space) with no mistakes, a sibling is never deleted or brought back, 30 days, thorough unit tests, then a release.

## Before

Deleting set `deletedAt` on the item and everything under it, but there was no Trash view, no restore, and nothing was ever deleted for good. Removing an attachment dropped it from the list at once (no way back) and left its file in S3 forever.

## Decided

- One delete = one moment: everything it takes shares `deletedAt`. Restore brings back that moment's items, never a sibling; a trashed place above comes back with only its own text. [0005](../decisions/0005-trash-moments-and-no-siblings.md)
- Attachments trash on their own (`Attachment.deletedAt`).
- Deleted for good = tombstone (`purgedAt`) that wins over any write; a daily job does the 30 days and frees text and unused files.
- When the place is in the trash, restore brings it too (no "restore elsewhere" for now). 30 days, fixed.
- Rules and diagrams: [07-trash.md](../architecture/07-trash.md).

## Done

| Where | What |
|---|---|
| `packages/core/src/trash.ts` | every rule as pure functions: trash, rows, restore, delete for good, expiry, cleanup |
| `apps/web` | Trash blade (Library), restore with a "this comes back too" question, Delete for good, Empty trash; attachments go to the trash; pulled tombstones beat pending edits; Help |
| `services/api` | item write over a tombstone refused; `purge.ts` daily job |
| `infra` | Purge Lambda + daily rule (21:30 UTC); files bucket: old versions expire after 7 days |

## Checked

- Core: 46 trash tests, including every item deleted and restored giving back the library exactly, and every pair of deletes (delete Y, then X, restore X) checked item by item against the rule. Turning on "a restored place brings its whole delete" makes 3 of them fail.
- App: 5 sync tests against a fake server that keeps tombstones (offline edit, offline restore, an edit typed during the pull, delete for good drops text, attachment trash). Removing the "tombstone beats pending" line makes the pull test fail.
- In a browser on the real Trash blade: the attachment-then-note case restored the note with its description and nothing else; Delete for good asked "and everything in it (1 more)"; Empty trash left live items alone.
