From chip to calendar
The chip is a link to a hidden event item, the same way a hidden description works today. The item is the truth: the Agenda reads it on the device, and a small worker on AWS writes it into the space’s calendar.
1 · Editor
You type @sun 3pm; a chip goes into the line.
2 · Event item
Hidden, its parent is the task. Saved on this device first.
3 · Sync API
/api/sync, the same path as notes. HTTPS and your sign-in.
4 · DynamoDB
Encrypted with your KMS key. A stream sees each change.
5 · Calendar worker
A Lambda creates, moves or deletes the calendar event.
Agenda blade
Reads event items and task due dates on the device. Works offline.
Your calendars
Google, Outlook or iCloud: the one each space picks in Settings.
Every calendar event links back: notes.mirsabbiralam.com/t/<task>#<event> opens the task and the chip flashes
The event item
Item {
  type: 'event'                 // hidden, like a description
  parentId: 'passport'          // the task or note it sits in
  title: null                   // null = the line's own text
  at: '2026-11-15T10:00+06:00'  // or '2026-11-15' for all day
  tz: 'Asia/Dhaka'
  done: false, private: false
  calendar: { provider: 'google', eventId: '…' }
}
// in the document, the chip is only { type: 'date', attrs: { eventId } }
Rules
Which calendar: the space’s choice from Settings › Calendars (the default plus per-space override you already have). One way first: Blade Notes writes to the calendar. Moving the event in Google does not move it back yet; two-way sync comes later. Private events: “Keep the text out of the calendar” sends only “Blade Notes reminder” and the link. Calendar sign-in: Google and Microsoft tokens are stored encrypted with the KMS key; only the calendar worker can read them, with events-only access. Offline: chips and the Agenda work without a network; the calendar catches up at the next sync.
