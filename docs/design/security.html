Security breakdown

Checked against the deployed BladeNotes stack on 11 Nov 2026. Phase 1 is what you asked for: encryption at rest with an AWS KMS key, encryption in transit, and the gaps around them. Phase 2 is your own key, for passwords.

Read this before storing passwords. A KMS key protects the stored data, but the app’s own server must be able to read your notes, so anyone who gets into your AWS account can read them too. Phase 1 makes that hard and logged. Only phase 2’s Secret blocks make it impossible: they open with a passphrase that never leaves your device.

Phase 2 · Secret blocks: your own key

Bank login •••••••••••• Reveal Copy
  • Select text and choose “Make secret”. It shows as dots, with Reveal and Copy.
  • Encrypted in the browser with AES-256-GCM. The key comes from your vault passphrase (PBKDF2, 600,000 rounds) and never leaves the device.
  • The server, AWS, backups and the calendar only ever hold ciphertext. Search skips secret text.
  • Locks again after 5 idle minutes. Copy clears the clipboard after 30 seconds where the browser allows it.
  • A lost passphrase means lost secrets, so a printable recovery key is made once.

Order of work

  1. Security headers and CSP (no data touched).
  2. KMS key; the table switches to it in place.
  3. S3 on the same key; existing files re-encrypted.
  4. Sign-in on file links.
  5. MFA on for your account: scan a QR code at the next sign-in.
  6. Alarms.

Your own key later: KMS accepts key material you bring. The table and bucket re-point to that key without downtime, so phase 1 does not lock you in.
